# Delivery and validation audit — 2026-09-09

Baseline: `048d3f695796c7dd185ab14c265c853da727b641`, default branch `agent/zero-operation-relay`.

## Confirmed defects and fixes

| Area | Failure condition and impact | Fix and regression evidence |
| --- | --- | --- |
| Broker envelope queue | A new envelope inserted after a pull can sort before its cursor when timestamps tie or the wall clock moves backward. The Gateway never sees that envelope. | Persist the queue timestamp high-water mark transactionally; retain it through TTL purge and restart. `BrokerStoreTest` covers late same-timestamp insertion, rollback, purge and reopen. |
| Broker receipt queue | A courier subscribes to an existing envelope after consuming a newer receipt. Filtering by receipt creation sequence permanently hides the old receipt. | Sequence availability per device; insertion triggers atomically enqueue both new receipts and newly subscribed historical receipts. Tests cover late subscription, idempotence and reopen. |
| Nearby automatic acceptance | The SDK accept task can remain suspended after the watchdog fires, keeping the platform event collector blocked. | Bound automatic acceptance itself; verify a subsequent discovered peer can be processed after the timeout. |
| Nearby explicit disconnect | A reconnect scheduled before a manual disconnect still runs afterward. | Cancel queued reconnects before disconnect/reject. Regression verifies no further connection request. |
| Nearby endpoint identity | A second discovery event can rebind one endpoint ID to another peer while the old peer remains connected. Subsequent packets are dropped or misattributed. | Refuse identity rebinding and guard initiation callbacks; regression verifies the original peer still receives its packets. |
| Cancellation and shutdown | Broad exception handlers turn cancellation into a retryable failure, changing stopped BLE UI state or incrementing outbox retry counts. | Propagate cancellation after necessary transport cleanup. Tests cover Nearby stop, stalled BLE stop and cancelled receipt flush. |
| BLE fairness | An unchanged receipt for the oldest request is repeatedly selected, starving other requests at the same delivery priority. Early local failures also have no cooldown. | Reserve a cooldown for every selected candidate, including unchanged receipt responses and local failures. A two-request regression verifies both receive a turn. |
| Packaged API verification | Scheduled checks use nonexistent manifest/upload routes. Another JVM check explicitly accepts HTTP 404, hiding the same problem. | Use the actual public rescue manifest and upload routes; parse a real manifest and require HTTP 200. Require HTTP 400 for malformed upload. Run the packaged workflow on changes to its definition. |

## Database compatibility

The envelope cursor retains its existing `stored_at:envelope_id` wire format. New queue timestamps are monotonic logical storage timestamps: under clock rollback or multiple inserts per millisecond they may be slightly ahead of wall time. Expiry continues to use the envelope TTL and current time.

Receipt polling keeps the existing numeric cursor and signed receipt payload. A new per-device delivery table is initialized above the legacy receipt sequence. Existing clients can therefore continue polling with persisted cursors. Migration may replay previously seen receipts once; signature verification and idempotent application remain required. Foreign-key cascades remove delivery rows when their source envelope/receipt is purged. Migration, repeated initialization and retention have explicit regression coverage.
